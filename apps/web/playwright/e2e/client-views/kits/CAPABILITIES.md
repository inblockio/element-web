# Rocket.Chat kit: capability map

Every Rocket.Chat function the kit renders is **wired** (fed by a shipped Element view-model through the
bridge, or a kit-local function that needs no Element data), **interim (D16)** (works through a bridge action that
calls Element's own client or dispatcher because no view-model carries it yet; the reason names the view-model it
awaits, and `tools/bump-element.sh` lists the row when a release ships a view-model with that name; treated like
wired: no N/A overlay) **hand-off (D26)** (Element's view-models feed the function and the action runs in another app, aqua-meet's call window; treated like wired: no N/A overlay) or **N/A** (no view-model source yet, or the function is a send the bridge cannot do). An N/A reason says "view-model X exists, not wired yet" when a shipped view-model covers the function but the
bridge hands over no field or action for it (an M4 candidate), and "no view-model" only when none exists. The kit reads the table below at build time: each N/A element is marked
`aria-disabled="true"` and `inert`, and gets a visible "N/A" badge in a body-level layer (`#kit-na-layer`, outside
React's tree). `e2e/capability-map.spec.ts` walks the same table.

Columns: `id` (unique), `selector` (CSS, in backticks), `presence` (`shown`: rendered on a room at 1280 px; `hidden`:
not rendered for the test user, the overlay still marks it if it appears; `user-menu`: rendered only while the user
menu is open, the spec opens it and checks those rows like `shown` ones), `status` (`wired` | `interim (D16)` | `N/A`), `reason`
(required for N/A and `interim (D16)`: the missing view-model source, or the view-model an interim function awaits).
